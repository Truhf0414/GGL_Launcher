# learnings — 活規則手冊（以後怎麼做）

## 驗功能看終點不看起點
**宣告某流程「可用」之前，grep 它的資料在終點（spawn 參數、寫檔、送出的請求）出現了沒；只讀起點（流程本體）不算驗。**
適用層：專案
證據：history 2026-09-11（auth token 沒傳到 spawn）

## 給 owner 裁決的預覽不剪裁
**請 owner 同意一個會改對外或刪資料的動作（發版、退版、刪檔）之前，工具的預覽報告整份給；不用 `rg`／`head` 挑行——挑的人想不到的那一行，正是會出事的那一行。報告太長就整份附檔，再另外摘要，摘要不能取代原文。**
適用層：專案
證據：history 2026-10-12（keepReleases 清掉 alpha1 封存）

## 「零命中」驗收先排除會講到它的註解
**用「某字串零命中」證明程式沒做某事（不 require 某模組、不呼叫某函式）之前，先想檔頭或註解會不會正好寫著這個字串——宣告「不做 X」的註解最常見。pattern 對準程式寫法（例如排除 `//` 開頭的行），再配一個真的會命中的對照檔。**
適用層：專案
證據：history 2026-10-11（④c 細部 plan：檔頭「不 require("electron")」）；history 2026-10-13（⑤a 驗收 3）

## 測試帳用探針實跑產生
**細部 plan 的測試帳（只改正式程式時，哪些既有測試會紅）在寫 plan 時就實跑：在 repo 外副本只改正式程式、跑全套，拿實際的紅燈清單當帳，不靠讀碼估。拆 `?.`、空 catch、預設值的批次尤其要跑——手刻的假元素只做了被呼叫到的方法，原本是防線在容忍它，防線一拆就浮出來。帳是實跑出來的，停止條件才只會在真的意外時觸發。**
適用層：專案
證據：history 2026-10-28（6d-1：R-C 備援 `bind`）；history 2026-10-28（6d-3：假元素缺 `closest`、假 main 回 `undefined`）；history 2026-10-28（6d-4：假元素缺 `closest`、`select`）

## 拆防線先找保證的負責人
**拆 `?.`、空 catch、預設值之前，先問它守的保證歸誰管，並在副本把保證拿掉看誰紅。有人接（產生端的測試或邊界檢查）才拆；沒人接就先補：在產生的地方驗、用的地方信任；隱性關係（誰包在誰裡面）改成有名字的依賴，併進既有機制，不另開一張表。降級本身是設計要的，才寫理由留著。最好的接手是不需要接手：先查那個依賴本身還該不該存在。**
適用層：專案
證據：history 2026-10-28（6d-4：`sync:status` 的 payload 形狀、`.topbar-pill` 的巢狀關係、設定視窗的空清單分支）

## 留下的位置當批就標出口
**每批驗收時，凡是決定留下的母體位置，當批就在 plan 寫上留-1～留-4（或安全閥）的字面與證據：留-1 寫跨過哪條邊界、留-2 附 commit、留-3 寫 U 項、留-4 並列 E／C；盤點描述被推翻的走退回、列進該批驗收單。只寫「留」加理由，等總結案再回頭對字面，就會在結案時整批卡住。**
適用層：專案
證據：history 2026-10-29（Phase 6 母體稽核的 28 處留-未標）

## 多行替換不用 `sd -F`
**跨多行的文字替換不用 `sd -F`（沒套上也回 exit 0）；改用 Edit 工具，或寫成 Python 腳本、替換前斷言錨點剛好出現一次。替換完照樣用測試或 `rg -F` 驗到「真的改到了」。**
適用層：專案
證據：history 2026-10-13（⑤b `sd -F` 多行取代）；history 2026-10-13（⑤c `sd -F` 多行取代）
